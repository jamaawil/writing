# Writing Site

A custom static site generator for essays, modeled on the approach described at
[michaeldeank.com/page/how-i-built-this](https://michaeldeank.com/page/how-i-built-this/).

No Hugo, no Jekyll — just `build.js` and the markdown libraries underneath those tools.

## Stack

- `gray-matter` — YAML frontmatter
- `remark-parse` + `remark-gfm` — markdown parsing (GitHub-flavored)
- `remark-rehype` + `rehype-stringify` — markdown → HTML

## Structure

```
content/
  essays/       published essays (title, date, topics, favorite, words)
  pages/        static pages: home, start-here, favorites, projects, how-i-built-this
  definitions/  dictionary terms
  library/      reading notes/responses (source, date)
  topics/       topic descriptions used by the Index page
static/
  css/, js/, images/   copied as-is into the build
build.js          the generator
public/           build output (gitignored, generated by `npm run build`)
```

## Usage

```
npm install
npm run build     # generates public/
npm run serve     # serve public/ locally
```

## Pages

Start Here · All Essays · Favorites · Index (by topic) · Library · Dictionary · Projects.
The "Aa" button in the header adjusts text size; the moon button toggles dark mode — both
persist via localStorage, matching the accessibility controls on the reference site.

## Adding content

Add a markdown file with frontmatter to the relevant `content/` subfolder and rebuild.
For example, a new essay:

```markdown
---
title: My New Essay
slug: my-new-essay
date: 2026-06-01
topics: [craft]
favorite: false
words: 900
---

Essay body in markdown...
```

## Deploying

Push to GitHub and connect the repo to Netlify (`netlify.toml` already sets the build
command and publish directory), or run `npm run build` and deploy the `public/` folder
to any static host.
